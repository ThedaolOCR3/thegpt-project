## 2. 실행 환경과 안전 점검

저장소의 `backend/.venv`는 삭제된 Python 3.12 경로를 참조해 실행할 수 없었다.
프로젝트 밖 임시 경로에 Python 3.14 가상환경을 만들고 현재 requirements 범위의
테스트 의존성만 설치했다.

실행 시 다음 안전 경계를 강제했다.

- `DATABASE_URL`: SQLite 메모리 DB URL로 Override
- LLM/Embedding: 비활성 또는 `127.0.0.1`의 연결되지 않는 더미 주소
- R2: 테스트 전용 더미 설정
- 웹 수집: `httpx.MockTransport`와 Fake DNS Resolver
- OCR Engine: Fake Engine/Mock 사용
- Admin API DB Dependency: Fake/Mock Session으로 Override
- 실제 외부 서비스 호출이 있는 Smoke Test는 실행하지 않음

## 8. 발견된 결함

### DEFECT-01 — Chunk Embedding ORM Vector 폭 불일치

- CASE ID: `TC-UT-04-08`
- 테스트: `test_chunk_embeddings_orm_width_matches_storage_contract`
- 실패 유형: A. 실제 Production 코드 계약 불일치
- 예상: ORM과 현재 저장 계약이 모두 `VECTOR(1024)`
- 실제:
  - `backend/app/models/generated.py`의 `ChunkEmbeddings.embedding`: `VECTOR(2048)`
  - `backend/app/services/admin_ocr.py`의 `NEON_VECTOR_DIMENSION`: `1024`
  - Migration `a1f3c9d2e8b4_narrow_chunk_embeddings_to_1024.py`: `1024`
- 실행 오류: `AssertionError: 2048 != 1024`
- 원인 추정: 2048→1024 Migration 이후 ORM 역생성 또는 수동 동기화가 누락됨
- 영향: ORM Metadata와 실제 DB/저장 검증 계약이 달라 타입 검사·Schema 생성·유지보수 시
  잘못된 Vector 폭을 기준으로 동작할 위험이 있음
- 수정 여부: 미수정
